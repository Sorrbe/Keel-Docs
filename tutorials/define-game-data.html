Define game data ​

You will define a typed Defs kind for a shop, read it from code, and see boot catch a typo.

1. A kind ​

Create src/ReplicatedStorage/Shared/Defs/Shop.luau:

luau
--!strict
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local Defs = require(ReplicatedStorage.Keel.Defs)

return Defs.kind("Shop", {
	DisplayName = Defs.String(40),
	Price = Defs.Int(1),
}, {
	pistol = { DisplayName = "Pistol", Price = 25 },
	rifle = { DisplayName = "Rifle", Price = 80 },
})

Defs.kind(name, shape, entries) takes the kind's name, the typed shape of every entry, and the entries keyed by id. Ids are permanent: they are what gets saved and sent, so never rename one.

Shared/Defs/ is loaded by both the server and the client, so a client can show the names and prices. Anything secret (drop tables, odds) goes in Server/Defs/ instead.

2. Read it ​

Anywhere in your code:

luau
local Shop = require(ReplicatedStorage.Shared.Defs.Shop)

Shop.Get("pistol")   -- { DisplayName = "Pistol", Price = 25 }, or nil if there is no such id
Shop.Has("rifle")    -- true
Shop.Ids()           -- { "pistol", "rifle" }, sorted

Add this to HelloService:Start() from the first tutorial and press Play to see it work:

luau
local Shop = require(ReplicatedStorage.Shared.Defs.Shop)

log:Info(`the shop sells {#Shop.Ids()} items; a pistol costs {(Shop.Get("pistol") :: any).Price}`)

3. Let boot catch a mistake ​

Boot checks every entry against its shape and every cross-reference. Add a second kind that points at the first. Create Shared/Defs/Loadouts.luau:

luau
--!strict
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local Defs = require(ReplicatedStorage.Keel.Defs)

return Defs.kind("Loadouts", {
	DisplayName = Defs.String(40),
	Weapon = Defs.Ref("Shop"), -- the id of a Shop entry
}, {
	starter = { DisplayName = "Starter", Weapon = "pistol" },
})

Press Play: it boots. Now misspell the reference, Weapon = "pistl", and press Play again. In Studio the server stops booting and the Output lists every problem together, along the lines of:

text
Defs: 1 problem(s) found:
- Loadouts.starter.Weapon: no Shop entry "pistl"

Fix the typo and it boots again.

Note

On a live server the same mistake does not stop the game. The broken entry is logged loudly and disabled, and so is any entry that referred to it.

4. Other field types ​

FieldAccepts
Defs.String(maxLength?), Defs.Number(min?, max?), Defs.Int(min?, max?), Defs.Bool()the basic values
Defs.OneOf({ "common", "rare" })one of a fixed set
Defs.Ref("Kind")the id of another kind's entry
Defs.List(field, maxLength?), Defs.Struct({ … })lists and fixed-shape tables
Defs.Optional(field)the same field, but may be nil

What you learned ​

  • A kind is one typed module; its entries are keyed by permanent ids.
  • Boot validates everything, so a typo is a boot error in Studio, not a bug a player finds.
  • Shared/Defs is visible to clients; Server/Defs is not.
