Sell a developer product ​

You will sell a pack of coins for Robux, grant it exactly once however often Roblox retries, and test it in Studio without spending Robux.

You need the saved Currency from Save and show player data.

1. Define the product ​

Open src/ReplicatedStorage/Shared/Defs/Products.luau. It ships with no entries. Add a field and one entry:

luau
--!strict
local ReplicatedStorage = game:GetService("ReplicatedStorage")

local Defs = require(ReplicatedStorage.Keel.Defs)
local Shapes = require(ReplicatedStorage.Keel.Purchases.Shapes)

return Defs.kind("Products", Shapes.Product({ DisplayName = Defs.String(40), Coins = Defs.Int(0) }), {
	coins_100 = { DisplayName = "100 Coins", ProductId = 123456, Coins = 100 },
})

Shapes.Product adds the fields every product needs (ProductId, and optional RandomItem, Odds, Giftable). You add your own (Coins).

Warning

123456 is a placeholder. A made-up id cannot be bought for real. Use it with the Studio test commands below, and replace it with your real developer product id from the Creator Hub before launch. Never store a price: prices differ by region, so the client asks Roblox for the price it shows.

Server/Main already passes your Products, Passes and Subscriptions kinds to Purchases.Configure.

2. Say what it grants ​

In ShopService (add "Purchases" and "Data" to its Dependencies), register a handler in Init:

luau
local Purchases = require(ServerScriptService.KeelServer.Purchases)
local Data = require(ServerScriptService.KeelServer.Data)

function ShopService:Init()
	Messages.Shop.Buy:OnServer(buy)

	Purchases.OnProduct("coins_100", function(player, entry, receipt)
		local data = Data.Get(player)
		data.Currency.Cash += entry.Coins -- change the player's data only; never wait here

		return true, { Currency = "Cash", Amount = entry.Coins, Balance = data.Currency.Cash }
	end)
end

The handler must not yield. Return true to say it was granted. The second return value is optional; with it, Keel logs an economy analytics event once the grant is saved.

Note

This handler changes data directly, which saves the change but does not send it to the client. To update the HUD at once, write through Replica.Set(player, "Currency.Cash", …) instead, as the shop does.

3. Test it without Robux ​

Press Play, press F2 to open the console, and run:

text
testbuy coins_100 3

This sends the same receipt three times, exactly as Roblox does when it retries. The handler runs once: the other two are recognised as already granted. Run testbuy coins_100 1 and the cash goes up again, because that is a new purchase.

testbuy and testpass work in Studio only. The console autocompletes product ids from your Products kind.

What Keel guarantees ​

For each receipt, Keel:

  1. refuses (NotProcessedYet, so Roblox retries) if there is no entry, no handler, or the player's data is not loaded;
  2. does not grant again if the PurchaseId is already in the player's saved log;
  3. runs your handler, then waits until a save containing the grant is confirmed before telling Roblox PurchaseGranted;
  4. fires Purchases.Granted once per purchase.

So a crash or a failed save never loses a purchase, and a retry never doubles it.

Warning

Never set ProcessReceipt yourself and never grant from PromptProductPurchaseFinished. Purchases owns the one callback.

Letting a player start the purchase ​

A client asks the server to start a purchase with Purchases.Buy("Product", id) (from Keel/Client/Purchases). The server refuses unknown items, restricted items and already-owned passes before Roblox's prompt appears. UI can ask Purchases.Info(…) for the regional price and Purchases.CanBuy(…) to hide what a player cannot have.

What you learned ​

  • A product is a Defs entry plus a handler that changes only the player's data.
  • Keel makes the grant exactly-once: de-duplicated by PurchaseId and confirmed saved first.
  • testbuy exercises the real receipt path in Studio.
