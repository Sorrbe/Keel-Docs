Connect Roblox Studio ​

Keel uses Studio's built-in Script Sync: the code lives in files under src/, and Studio keeps the scripts in step with them. Script Sync can only sync Folders, so a game has six root Folders.

Studio cannot script the Script Sync connect, so there is one manual step per Folder. The Keel Setup plugin does everything around it.

1. Install the Keel Setup plugin (once per computer) ​

Every game has the plugin at tools/KeelSetup.lua.

  1. In Studio, open the Plugins tab and click Plugins Folder.
  2. Copy tools/KeelSetup.lua into that folder (on Windows, %LOCALAPPDATA%\Roblox\Plugins).
  3. Restart Studio. A Keel toolbar with a Keel Setup button appears in the Plugins tab.

To update the plugin after a Keel update, copy the file again.

2. Press Keel Setup ​

Open your place and click Keel Setup. It:

  • creates any missing Folder from the table below (an existing Folder is never touched);
  • creates the optional place attributes with their defaults, only where they have no value yet (FastSpawn, LogOff, Version on ReplicatedStorage; FreshData, DataVersion on ServerScriptService);
  • opens a checklist that shows which Folders exist and the disk folder each one connects to.

It is safe to press twice, and the change can be undone with Ctrl+Z.

3. Connect each Folder (once per place) ​

Disk folderStudio FolderHolds
src/ReplicatedStorage/Keel/ReplicatedStorage.KeelKeel, shared parts
src/ReplicatedStorage/Shared/ReplicatedStorage.Sharedthis game's shared code: Defs, the Net list
src/ServerScriptService/KeelServer/ServerScriptService.KeelServerKeel, server-only parts
src/ServerScriptService/Server/ServerScriptService.Serverthis game's server code
src/ReplicatedFirst/Client/ReplicatedFirst.Clientall of this game's client code
src/StarterPlayer/StarterPlayerScripts/Boot/StarterPlayer.StarterPlayerScripts.Bootonly Boot.local.luau

For each row:

  1. Right-click the Folder, then Script Sync, then Sync with Directory.
  2. Pick the matching disk folder and choose Keep Disk (the files win).
  3. Turn auto-resume on.

After that, everything inside a root syncs both ways on its own.

Note

The connections belong to the place on your computer. They are not saved inside the place file, so copying or re-saving a place does not carry them: a template place file with the Folders already connected was tried, and the scripts appeared but the connections did not. Do the connects once for each place you open on a new computer.

Doing it without the plugin ​

The plugin only saves you creating the Folders and attributes by hand. To skip it, create a Folder with each name from the table under its service in Studio, then do step 3.

Press Play ​

Start a playtest. The Output window should show:

text
[Loader] Server booted …
[Loader] Client booted …

Those two lines mean the server and the client both started. If they do not appear, see Troubleshooting.

Warning

Client code lives in ReplicatedFirst, not in StarterPlayerScripts. Scripts in StarterPlayerScripts are cloned into each player when the game runs, so clicking an error opens the clone and edits made there are lost. Modules in ReplicatedFirst are not cloned, so errors open the real source.

Optional place settings ​

The attributes the plugin creates are optional: each has a default written in its script, so the game works if you never set them. See Tooling and hooks.
