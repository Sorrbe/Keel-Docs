Changelog ​

Current version: 0.4.0. This page is generated from CHANGELOG.md in the Keel repo by npm run gen:changelog; edit that file, not this one.

0.4.0 ​

Added ​

  • docs-check Stop hook (.claude/hooks/docs-check.js): when Claude ends a turn, flags uncommitted src/ files whose Systems/ notes are older than the code, or that no note lists, in one line, once.
  • vault-notes skill: the vault rules (where notes go, keeping them small and current) and the step close after a build step passes its check.
  • design-talk skill: routes game-design talk to Design/, Brainstorm/ or chat; brainstorm note format and promotion.
  • Vault skeleton in Starter/Docs/ (starter files, copied once by new): Done.md, Look Later.md, Design/ (Design Index, Design Status, System Spec Template), Brainstorm/Brainstorm Status.md, Systems/ (Game Already Exists, Game Tooling). Empty tables and headings: the one layout every Keel game shares.

Changed ​

  • Starter Status.md is Current / Last / Next only; finished work goes to Done.md, open decisions to Look Later.md.
  • Starter CLAUDE.md is about a third of its old size: the vault and design rules moved into the two skills, the layout rules into luau-layout. It no longer tells a game to add rows to Keel's read-only Already Exists.md (the game's own is Game Already Exists.md).
  • /verify step 2 checks Status against the git log and Done.md (Current, Last and its date, Next; Last is Done.md's last row).
  • .gitignore ignores Docs/Completed Build Orders/.

Migration ​

  • Existing games: update adds the hook, the two skills and the new /verify. Starter files are never copied by update, so register the hook yourself: add a Stop entry running node "$CLAUDE_PROJECT_DIR/.claude/hooks/docs-check.js" to .claude/settings.json. Copy any skeleton notes you lack from Starter/Docs/. A game whose CLAUDE.md holds the vault rules can drop them in favour of the skills.

0.3.2 ​

Fixed ​

  • The note-lookup hook's header comment pointed at Docs/Systems/Tooling.md, which in a game is Docs/Systems/Keel/Tooling.md; it now names both (comment only, no behaviour change).

Migration ​

  • None.

0.3.1 ​

Changed ​

  • Release process only (no Luau changed): every version stays a Git tag, and only a major version (v1.0.0, v2.0.0, ...) also gets a GitHub Release. A new workflow, "Release (majors only)", creates it when the tag is pushed, with notes from this changelog (the major's Migration first, then everything since the previous major). Minors, patches and every 0.x version stay tags only. See the Releasing Keel guide.

Migration ​

  • None. keel.js still installs from tags; nothing in a game changes.

0.3.0 ​

Added ​

  • Frame hooks. Any Service, Controller or System can define PreSimulation(dt) (every frame, before physics: for velocities and forces physics must see this frame) and PreRender(dt) (every frame, just before drawing, client only: for the camera). The Loader hands them to the Scheduler when Start returns, like Update. They get the same protection as Update: guarded, slow calls logged, and a hook that waits is stopped. Unity's closest are FixedUpdate and LateUpdate, but Roblox has no fixed step: dt is the frame's real time.
  • Scheduler.AddFrame(module, "PreSimulation" | "PreRender"). Game code rarely calls it; the Loader does.
  • Types.Module has the two optional fields.

Changed ​

  • Scheduler.Remove(module) stops every hook of the module, not only Update.
  • Scheduler log lines name the hook (Name.PreSimulation: …); Update lines read as before.
  • The Loader stops the boot if a module's PreSimulation or PreRender isn't a function, or if a server module has a PreRender (there is no rendering on the server).

Migration ​

  • None. Modules without the new hooks behave exactly as before. A module that connects its own RunService.PreSimulation or PreRender can move that code into the matching method to get the Scheduler's guard and logging.

0.2.3 ​

Added ​

  • LogOff understands * (mute every tag) and -Name (exempt one tag from *): *,-Replica mutes everything except Replica.
  • Log.Only(tag) writes that for you. Log.Set('*', enabled) mutes or restores all tags.
  • Console: log &lt;tag> only mutes every other tag, and log * off / log * on mute or restore everything. The tag argument autocompletes *.

Changed ​

  • The log command's reply lists the LogOff entries now set (for example LogOff: *, -Replica) instead of muted: ....

Migration ​

  • None. An existing LogOff value such as Data,Replica works as before.

0.2.2 ​

Fixed ​

  • keel.js update no longer deletes and recreates the owned folders (Keel, KeelServer, ...). It overwrites files in place, deletes only files Keel dropped (and folders left empty), so Studio's Script Sync stays connected and you no longer reconnect after an update.

Migration ​

  • The update to 0.2.2 still runs the old keel.js, so reconnect Script Sync on Keel and KeelServer once after it. Updates after that keep the connection.

0.2.1 ​

Changed ​

  • Docs only: the Replica and State note records that the two-player privacy check passed live (a client reads other players' Public state and nil for their Owner state; right after joining it reads nil until the snapshot arrives, so use State.Observe). No code changed.

Migration ​

  • None.

0.2.0 ​

Added ​

  • Keel Setup, a Studio plugin (tools/KeelSetup.lua, an owned file) that creates the six root Folders and the optional place attributes, and lists the Script Sync connects still to make. Studio cannot script the connect itself, and a template place file does not keep the connections, so the connects stay manual.
  • keel.js new prints the plugin install step and the next steps in Studio.
  • A documentation site in site/ (VitePress): getting started, tutorials, guides, an API reference generated from the source, and a changelog page. Not copied into games.

Changed ​

  • Releasing now requires every change to be documented in the same release, with deprecations, new features and kits recorded in the changelog (see site/guides/releasing-keel.md).

Migration ​

  • None. After node tools/keel.js update v0.2.0 a game has tools/KeelSetup.lua; copy it into Studio's Plugins folder if you want the plugin.

0.1.1 ​

keel.js writes text files with LF line endings (a Windows clone had CRLF, which StyLua rejected). New games get a .gitattributes that keeps LF on checkout.

0.1.0 ​

First version. Extracted from StealTheGun (commit 7831be3): Loader, Scheduler, Signal, Trove, Log, Net (Packet), Defs, Entity, Data (ProfileStore), State and Replica, Client layer (Input, UIController, View, Widget), Console (Cmdr), Purchases, Policy, LiveDefs, the unit test runner and its specs, plus the starter game files, tooling and notes.
