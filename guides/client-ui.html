Client UI ​

How the client binds input, shows screens, builds reusable UI pieces and covers the load.

There is no Controller base: a Controller is any table the Loader boots (Name, Init, Start; the shape is Types.Module). Controllers are the only client modules that send network messages.

FileWhat it is
Keel/Client/Input.luaubinds an action to keyboard, gamepad or touch (wraps ContextActionService)
Keel/Client/UIController.luauregistry of Views: open, close, toggle by name; exclusive menus close each other
Keel/Client/View.luauone screen or menu: builds its ScreenGui once, then Open and Close
Keel/Client/Widget.luaua reusable UI piece: a root GuiObject plus a Trove
Client/LoadingScreen.luau, Client/Loading.local.luauthe loading cover (in ReplicatedFirst, so it runs before Keel has arrived)
Client/UI/Views/, Client/UI/Widgets/this game's Views and Widgets
Keel/Client/Console.luaubinds F2 to the admin console. See Console
Keel/Client/Purchases.luaufor shop UI: Buy, Info, CanBuy, Odds. See Purchases

These Keel modules are plain modules, not booted by the Loader (the client Loader boots only Client/Controllers).

Input ​

luau
local binding = Input.Bind("Interact", {
	Keyboard = Enum.KeyCode.E,
	Gamepad = Enum.KeyCode.ButtonX,
	Touch = true,  -- also an on-screen button
	Title = "Use", -- its text
}, function(began: boolean) end)

binding:Unbind() -- or Input.Unbind("Interact")

A bound action takes the input (the key does nothing else while bound). Binding the same name twice errors: unbind first.

Views and UIController ​

luau
-- Client/UI/Views/Shop.luau
return View.new({
	Name = "Shop",
	Exclusive = true, -- opening it closes other exclusive views
	Build = function(gui: ScreenGui, trove)
		-- make the screen; put every State.Observe and connection in the trove
	end,
})
luau
UIController.Open("Shop")
UIController.Close("Shop")
UIController.Toggle("Shop")
-- view.Opened and view.Closed are Signals
  • Views read State and call Controllers; they never send Net messages (a rule, not enforced). Build runs once, on the first Open; after that Open and Close only switch gui.Enabled, so a closed view keeps observing State.
  • UIController.Boot(Client/UI/Views) (called by Client/Main, before the Controllers boot) requires every module there and registers the View each returns, so a Controller's Start can already open one. A View outside that folder: UIController.Register(view). Opening or closing an unknown name errors; two Views with one name error.

Widgets ​

A Widget is a builder function that makes the Gui and binds it to State through the widget's Trove, so widget:Destroy() cleans everything:

luau
return function(parent: Instance, path: string): Widget.Widget
	local label = Instance.new("TextLabel")
	local widget = Widget.new(label)
	widget.Trove:Add(State.Observe(path, function(value)
		label.Text = tostring(value)
	end))
	widget:SetParent(parent)

	return widget
end

Loading screen ​

Loading.local (an early LocalScript) calls LoadingScreen.Show(); Client/Main calls LoadingScreen.Hide() after Net.ClientReady().

  • Plain text "Loading" on a full-screen cover.
  • Safety timeout: if Hide never comes (boot failed), it hides itself after 20 seconds with a warning.
  • FastSpawn (Studio only): attribute FastSpawn = true on ReplicatedStorage hides it as soon as the game has loaded.

See the Input, View, UIController and Widget API pages. A worked example: Save and show player data.
