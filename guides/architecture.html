Architecture ​

This page records what Keel decided and why. Each system has its own guide with the details.

Foundations ​

DecisionWhy
One shared framework, copied unchanged into every game. Game code is built on top of it and never edits it.A bug is fixed once, and a new game starts with loading, saving and networking already working.
Keel's master copy is its own repository. Each game commits a full copy; keel.json records the version and tools/keel.js installs and updates it from a tag.Each game is self-contained and stays on a known version. Upgrading is a deliberate step.
Keel is written in-house, with only four external libraries copied in (Trove, Packet, ProfileStore, Cmdr), each at one recorded version.Full control of the core. Libraries are used only where they replace hard, proven work.
The server is the authority for currency, inventory, progress, damage, health, cooldowns, purchases and round state. The client is trusted only for its own movement, camera, UI and cosmetic effects.Clients can be exploited. The client sends what it wants to do; the server decides.
Keel is --!strict. Game code is strict by default and may opt out per file.Typos and wrong-shaped data are caught before pressing Play.

Layout ​

Script Sync can only sync Folders, so there are six root Folders (see Folders and boot). Server code is never sent to clients: KeelServer and Server live in ServerScriptService. Client code lives in ReplicatedFirst, which is not cloned into players the way StarterPlayerScripts is.

How code runs ​

  • One entry per side. Server/Main.server.luau and the Boot LocalScript. A single place controls start order, so scripts never race.
  • Modules declare their dependencies and the Loader sorts them. Folder order never matters, and a cycle stops boot with an error.
  • Lifecycle: Init wires things up and must not wait or call other modules. Start runs after every Init and may wait. Update is optional and driven by one central Scheduler, as are the optional frame hooks PreSimulation (every frame, before physics) and PreRender (every frame, before drawing, client only).
  • Every call is guarded. Init, Start, Update and the frame hooks are wrapped in pcall and timed, so one broken module logs an error instead of stopping everything.
  • Services and Controllers. Server systems are Services; client systems are Controllers.
  • Dependencies point one way. Server: Services, then Components, then Shared. Client: UI, then Controllers, then Shared.
  • Lower layers report upward through typed Signals (Health.Died:Connect(...)). There is no global event bus keyed by name strings, because those hide who listens and fail silently on typos.

State replicates; messages carry intent ​

Ongoing values (cash, health, inventory) reach clients as state they watch. Network messages are only for requests ("buy this") and one-off moments (a hit landed). Each piece of player state declares its audience:

AudienceReceives itExamples
Owneronly that playercash, inventory, quests, cooldowns
Publiceveryonelevel, team, equipped item
Nonethe server onlyanti-cheat counters

Data about a world object (an enemy's health, a door) goes in attributes on its model, so with streaming on it arrives and leaves with the model. See State and Replica.

Networking ​

One central list in Shared/Net holds every message, named Feature.Action. Each definition declares argument types, ranges and rate limits, and Net checks them before any handler runs. A client may send only messages that declare a Rate. See Networking.

Player data ​

Saving wraps ProfileStore: a session lock (one server owns a profile), load retries, and a shutdown that waits for saves. Keel adds kicking on load failure, a 60-second autosave, versioned migrations, a store name per environment (Studio, Test, Live) and purchase de-duplication. Components declare their own saved shape. See Player data.

Game data (Defs) ​

Defs are static, authored data about what things are, separate from player data (what each player has). One typed module per kind, permanent string ids, and boot-time validation of every entry and cross-reference. In Studio a broken entry stops boot; on a live server only that entry is disabled. See Defs.

Client and UI ​

Controllers are the only client modules that send network messages. Input is bound by action, not by key. UI is hand-built: Views (one per screen), Widgets (reusable pieces) and a UIController that opens and closes them. See Client UI.

External libraries ​

Each is an unchanged copy of one pinned version in a Vendor/ folder, reached only through a re-export file next to it, so swapping a library changes one file.

LibraryUsed for
Trove (Sleitnick)cleanup bag for connections, instances and threads
Packet (Suphi Kaner)binary networking under Keel's Net
ProfileStore (loleris)session-locked saving under Data
Cmdr (evaera)the admin console

Signal (typed events) is written in-house. Details: Tooling and hooks.
