Purchases and policy ​

Selling things for Robux without granting twice, losing a purchase, or breaking Roblox policy: developer products, game passes, subscriptions, paid random items, gifts and trades, regional pricing, and Roblox's policy flags.

Setup (game side) ​

luau
-- Shared/Defs/Products.luau
return Defs.kind("Products", Shapes.Product({ DisplayName = Defs.String(40), Coins = Defs.Int(0) }), {
	coins_100 = { DisplayName = "100 Coins", ProductId = 123456, Coins = 100 },
})

Server/Main already calls Purchases.Configure with your Products, Passes and Subscriptions kinds. Then, in a Service (add "Purchases" to its Dependencies), in Init or Start:

luau
Purchases.OnProduct("coins_100", function(player, entry, receipt)
	local data = Data.Get(player)
	data.Currency.Cash += entry.Coins -- change data only; never wait

	return true, { Currency = "Cash", Amount = entry.Coins, Balance = data.Currency.Cash }
end)

Shapes.Product gives ProductId, RandomItem?, Odds?, Giftable?; Shapes.Pass gives PassId; Shapes.Subscription gives SubscriptionId. A game kind adds its own fields. Prices are never stored: they differ by region.

Developer products: granting exactly once ​

Purchases sets Roblox's single ProcessReceipt callback. For each receipt:

  1. No Products entry with that ProductId, or no OnProduct handler, answers NotProcessedYet (Roblox offers it again) and logs an error.
  2. A player not in this server, or whose data is not loaded, answers NotProcessedYet.
  3. A PurchaseId already in the player's saved receipt log is not granted again: the log is saved if needed, and the answer is PurchaseGranted.
  4. Otherwise the handler runs. It must not yield. If it errors, waits, or returns false, the answer is NotProcessedYet.
  5. The PurchaseId is added to the log (the last 100 kept) and Data.SaveNow waits until a save that contains it is confirmed before answering PurchaseGranted. If the save cannot be confirmed, the answer is NotProcessedYet; the retry finds the id, saves, and answers PurchaseGranted without granting again.
  6. Only then: the economy analytics event (if the handler returned { Currency, Amount, Balance }) and the Purchases.Granted signal, once per purchase.

Warning

Never grant from PromptProductPurchaseFinished: it fires when a prompt closes, not when Robux were spent. Never set ProcessReceipt yourself; Purchases owns it. The handler should change only the player's data: if it changes something else and then errors, nothing undoes that.

Game passes: ask, never remember ​

luau
Purchases.OwnsPass(player, "vip")            -- a live check every time it matters
Purchases.OwnsPassPermanently(player, "vip") -- purchased (not a free trial): for permanent grants
  • Never save "owns VIP" or anything a pass grants. Free trials and refunds end ownership without any event. Apply benefits at runtime from a live check.
  • The checks fail closed: if Roblox cannot be reached the answer is false.
  • Account.Passes.<id> mirrors ownership for the client. Purchases.PassChanged fires.

Subscriptions ​

Purchases.IsSubscribed(player, id) is refreshed at join and on Players.UserSubscriptionStatusChanged, and mirrored to Account.Subscriptions.<id>. Purchases.SubscriptionChanged fires. Offered only where policy allows (IsEligibleToPurchaseSubscription).

Starting a purchase ​

The client sends Purchases.Buy("Product" | "Pass" | "Subscription", id) (a Defs id, rate-limited to 2 per second). The server answers ok, reason and only then shows Roblox's prompt. It refuses:

CaseReason shown
unknown id or kindunknown item
a RandomItem product when paid random items are restricted (or policy not known yet)not available in your region
a pass the player already ownsalready owned
a subscription when not eligiblenot available in your region
an active subscriberalready subscribed
Roblox cannot say whether they own the passtry again later

Paid random items ​

Mark the product RandomItem = true and list its Odds ({ Label, Chance } adding up to 1): Roblox requires odds to be disclosed. Shapes.Problems checks this and that no two products share a ProductId; in Studio a problem stops the boot, on a live server it is logged. UI shows Purchases.Odds(entry) and hides the offer when Purchases.CanBuy says no.

Regional pricing ​

  • Never hard-code or save a price. UI asks Roblox on the client with Purchases.Info(kind, entry), so it matches the price in the purchase prompt. Cached for 60 seconds.
  • Gifts and trades: Purchases.CanTransfer(from, to, "Gift" | "Trade") allows a gift from an equal or higher price level to a lower one, and a trade only between equal levels. Both players need IsPaidItemTradingAllowed. Anything unknown is refused. Any game feature that moves purchased items between players must call it.

Policy ​

At join the server calls PolicyService:GetPolicyInfoForPlayerAsync (three tries, then it fails closed: restricted flags true, allowed flags false, with a warning). Flags kept: ArePaidRandomItemsRestricted, IsPaidItemTradingAllowed, IsEligibleToPurchaseSubscription, IsContentSharingAllowed, AreAdsAllowed, IsSubjectToChinaPolicies. They are mirrored to Account.Policy; until Roblox answers they hold the strictest values. Any feature that Roblox policy restricts should read Policy.Get(player) before offering it.

Testing in Studio ​

luau
Purchases.TestPurchase(player, "coins_100", purchaseId?)   -- the real receipt path, no Robux
Purchases.SetTestPass(player, "vip", true | false | nil)    -- pretend a pass is owned; nil clears

Console: testbuy <product> [times] and testpass <pass> <on|off|clear>. Both work in Studio only and error elsewhere. An entry with a made-up Roblox id cannot be bought for real; use TestMode for anything not yet created in the Creator Hub.
