Defs (game data) ​

Static, authored game data (what things are): items, enemies, shop lists. Each kind has a typed shape, and boot checks every entry and every cross-reference, so a typo is caught before a player is affected.

Where Defs live ​

PathHolds
Shared/Defs/kinds and values clients need to display and predict
Shared/Defs/Rules.luaugame-wide single values (StartingCash, RespawnSeconds, ...). Plain values, not a kind
Server/Defs/server-only kinds (drop tables, AI tuning). Never sent to clients
Shared/Defs/Products, Passes, Subscriptionsthe Robux things this game sells. See Purchases
Server/Defs/Admins.luau, LiveKeys.luauplain lists, not kinds: console admins, and the keys live configs may change

Defining a kind ​

One module per kind, returning the Kind:

luau
local Items = Defs.kind("Items", {
	DisplayName = Defs.String(40),
	Price = Defs.Int(0),
	Weapon = Defs.Optional(Defs.Ref("Weapons")),
}, {
	sword_iron = { DisplayName = "Iron Sword", Price = 50, Weapon = "blade" },
})

return Items
FieldAccepts
Defs.String(maxLength?)a string
Defs.Number(min?, max?)a finite number
Defs.Int(min?, max?)a whole number
Defs.Bool()true or false
Defs.OneOf(values)one of a fixed set of strings: an array, or a dictionary's keys
Defs.Ref("Kind")the id of an entry of another kind; must exist
Defs.List(field, maxLength?)a list, each item checked by field
Defs.Struct({ key = field })a table with exactly those keys
Defs.Optional(field)the same field, but may be nil

Reading: Items.Get(id) (the entry or nil), Items.Has(id), Items.Ids() (sorted), Items.Entries (read-only; Net.OneOf(Items.Entries) works), Items.Name. By kind name: Defs.IdsOf("Items").

Behaviour to rely on ​

  • Ids are lowercase letters, digits and _, starting with a letter. They are saved and sent: never rename one. Display text comes from fields like DisplayName.
  • Boot: Server/Main calls Defs.Boot(Shared/Defs, Server/Defs) after Shared/Net and before the Loader. Client/Main calls Defs.Boot(Shared/Defs). Keep Defs modules in those folders: a kind in a module nothing requires is not registered.
  • Validate checks each entry: id format, no field outside the shape, every required field present, each value passes its field. Problems read like Items.sword_iron.Weapon: no Weapons entry "blde".
  • In Studio any problem errors with all problems listed, so boot stops. On live servers each broken entry is logged and disabled, and so is any entry that referred to it.
  • Layering: Shared kinds cannot refer to Server kinds (the client never has them); Server kinds may refer to Shared ones.
  • Entries are frozen after validation. A malformed shape errors at Defs.kind, as does a duplicate kind name.
  • Formulas go beside their kind as typed functions, not in a Util folder, so server and client compute the same result.

Live tuning (server-only Defs) ​

A server-only value can be changed on running servers without a publish, and A/B tested, through Roblox ConfigService (Creator Hub, Configs).

  • Allowlist: Server/Defs/LiveKeys.luau lists the keys ("Kind.entry_id.Field") that may change; only those are read. Create a config of exactly that name in the Creator Hub; delete it to go back to the authored value. Roblox allows 100 keys per experience, and values reach running servers within about 5 minutes.
  • Defs.Override(kind, id, field, value) returns ok, reason, and Defs.Restore(kind, id, field) puts it back. Refused for a kind clients can see, an unknown kind, entry or field, a value the field rejects, and any value containing a Ref. Code must read entries through Kind.Get each time, not keep one, to see a change.
  • LiveDefs (a Service) applies the ConfigService values. A missing value restores the authored one; an invalid value is logged and leaves the authored one in force. The console command livedefs prints what is applied.
  • Test in Studio without publishing: from the server command bar, game:GetService("ConfigService"):SetTestingValue("<Kind>.<entry_id>.<Field>", value) (the key must be in LiveKeys).

Tip

Values clients display need a publish to change. A Rules value worth tuning live belongs in Server/Defs instead.

See the Defs, Fields and LiveDefs API pages.
