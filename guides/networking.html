Networking ​

How server and client talk: Keel/Net on top of Packet. Every message a client sends is rate-limited and checked before any handler runs, and server messages to a joining player wait until that player's client is ready.

FileWhat it is
Keel/Net/init.luauthe API: defining messages, sending, listening, the ready handshake, the unreliable channel
Keel/Net/Args.luauargument types (Net.Int, Net.String, ...), each a Fields field plus the Packet type that encodes it
Keel/Net/Screen.luauthe server's receive check: Rate, then Args, plus throttled rejection warnings
Keel/Packet.luaure-export of the vendored Packet. Only Net uses it
Shared/Net.luauthis game's message list, the one place every message is defined

Defining a message ​

All messages go in Shared/Net.luau, grouped by feature. Names are Feature.Action.

luau
return {
	Shop = {
		Buy = Net.event("Shop.Buy", { Net.OneOf(Defs.Items), Net.Int(1, 99) }, { Rate = 5 }),
		Opened = Net.broadcast("Shop.Opened", { Net.String(50) }),
	},
}

Use them from Services and Controllers:

luau
local Messages = require(ReplicatedStorage.Shared.Net)
Messages.Shop.Buy:FireServer("sword_iron", 1)

Kinds ​

KindClientServer
Net.event(name, args, opts?): fire-and-forget, either way:FireServer(...), :OnClient(fn):FireClient(player, ...), :OnServer(fn(player, ...))
Net.request(name, args, opts): needs an answer:Invoke(...) returns ok, reason? (waits):OnInvoke(fn(player, ...)) returns ok, reason? (one handler)
Net.broadcast(name, args): server to many:OnClient(fn):FireAll(...), :FireNear(position, radius, ...)
Net.unreliable(name, args, opts?): high-rate, replaceablesame as eventsame as event, plus :FireAll(...)

Listener methods return a Connection (:Disconnect()).

Argument types ​

TypeAccepts
Net.Int(min, max)whole numbers in range; encoded in the smallest fitting integer
Net.Number(min, max)finite numbers in range (32-bit float, about 7 significant digits)
Net.String(maxLength)strings up to maxLength bytes (at most 65535)
Net.OneOf(values)one of a fixed set of strings; an array gives values, a dictionary its keys
Net.Bool()true or false
Net.Vector3()a Vector3 with finite components
Net.Instance(className?)an Instance (IsA(className)). Arrives as nil if the client cannot see it, which fails the check
Net.Array(arg, maxLength)a list, each item checked by arg
Net.Struct({ key = arg })a table with exactly those keys
Net.Any()plain data of any shape. Server-to-client only.

There is no "any" type and no optional argument: every value has a shape. Net arguments need both bounds, because they pick the Packet type.

Behaviour to rely on ​

  • A client may send a message only if it has { Rate = n } (sends per second, per player). Without a Rate, FireServer and OnServer error, and the server drops client sends. request always needs a Rate; broadcast never has one.
  • Server receive order: Rate (a token bucket) then argument checks (which also reject extra values) then handlers. A rejected event is dropped. A rejected request answers false, "rate limited" or false, "invalid".
  • Rejections log a Warn like [Net] Bob sent Shop.Buy: arg 2: must be at most 99, got 500 (dropped), at most once per 10 s per player per message.
  • Handlers still check game rules: ownership, distance, cooldowns, money.
  • Requests: a handler that errors, or returns something other than (boolean, string?), answers false, "error". No handler gives false, "no handler". No answer within 10 s gives false, "timeout".
  • Every send checks its own arguments and errors at the caller, so a bad value you send surfaces where it was made.
  • Handshake: server sends to a player whose client is not ready are queued, up to 256 (then dropped with one Warn), and delivered in order once it is ready. On the server, Net.IsReady(player) and Net.PlayerReady tell you when a client is listening.
  • Boot: Server/Main requires Shared/Net before booting anything. Client/Main requires it, calls Net.WaitForServer(), boots the Controllers (their Init connects listeners), then calls Net.ClientReady().
  • Unreliable messages travel over one UnreliableRemoteEvent. Payloads over 900 bytes error at the sender. They may arrive out of order or not at all.

Limits ​

  • 256 messages per game, Net's internal Keel.Ready included. The 257th definition errors.
  • 8000 bytes per player per frame from a client. Packet drops the rest.
  • 128 requests waiting at once per client.

Tip

Prefer an event plus a state change over a request. Then nothing waits on a reply. And let the server pick values itself whenever it can: never trust a number the client sends when the server can work the answer out.
