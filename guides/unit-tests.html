Unit tests ​

Small tests that run one module with known inputs and check the result, so a change that breaks something elsewhere is caught in seconds. Keel has its own runner (no Jest-Lua or TestEZ).

Running them ​

Start a playtest, switch the command bar to the server, and run:

luau
require(game.ServerScriptService.KeelServer.Tests.Runner).Run()          -- every spec
require(game.ServerScriptService.KeelServer.Tests.Runner).Run("Signal")  -- specs whose name contains "Signal"
  • Each failure prints a [FAIL] Spec > test name line with the file, line and what was expected versus got. The run ends with [Tests] N passed, M failed. Run also returns { passed, failed }.
  • Some tests break things on purpose (an erroring Signal handler, a module whose Init crashes). Their red [Loader] and [Scheduler] errors are expected. Only [FAIL] lines count.
  • A full run takes about 5 seconds, mostly the Scheduler tests, which wait real frames.
  • require caches modules for the whole playtest. To test code you just changed, stop and start the playtest again.

Writing a spec ​

  • Where: Keel's own tests are in KeelServer/Tests/ (they travel with Keel). Your game's tests go in Server/Tests/ (subfolders are fine). Both are server-only, so tests never reach clients.
  • Name: Name.spec.luau. Script Sync turns it into a ModuleScript named Name.spec, and the runner picks up every ModuleScript ending in .spec.
  • Shape: the spec returns function(t):
luau
--!strict
local Runner = require(game.ServerScriptService.KeelServer.Tests.Runner) -- for the T type
local Upgrades = require(game.ReplicatedStorage.Shared.Defs.Upgrades)

return function(t: Runner.T)
	local expect = t.expect

	t.test("CostAt doubles per level", function()
		expect.equal(Upgrades.CostAt(2), Upgrades.CostAt(1) * 2)
	end)
end

Checks ​

CheckPasses when
equal(actual, expected)actual == expected
deepEqual(actual, expected)same table contents, nested; a failure names the first difference, such as Currency.Cash: expected 5, got 4
near(actual, expected, within?)numbers within within (default 1e-6)
truthy(value) / falsy(value)value is truthy / falsy
throws(fn, contains?)fn errors (and the message contains contains); returns the message

Behaviour to rely on ​

  • Each test runs in its own thread and may wait (task.wait, Signal:Wait). One still waiting after 5 seconds fails.
  • A failing test, or a spec that errors outside a test, never stops the other tests.
  • Tests run in the order they are written; specs run sorted by full name.
  • Write tests against the contract in the module's header, not against what the code happens to do.

What gets tests: Keel modules, Defs formulas and data migrations. Game features are checked by playing.

The Loader never boots tests ​

The Loader skips any Folder named Tests, so KeelServer/Tests is never booted even though Main.server.luau boots KeelServer.

What Keel's specs cover ​

Signal, Trove, Loader, Scheduler, Net, Defs, Entity, Client (View, UIController, Widget), State, Replica, Data, Purchases, LiveDefs and Console. Each lives in KeelServer/Tests/<Name>.spec.luau; read one to see the style.

See the Runner API page.
