Tooling and hooks ​

The development setup around the code: formatting, linting, editor support and how outside libraries are kept. The workflow is Script Sync and GitHub only: no Rojo, Rokit, Aftman or Wally.

Principle: mechanical, repeated jobs (lookups, checks, formatting, reminders) are done by hooks, not by an AI assistant reading and reasoning each time. A hook runs on your PC and hands back only a short result.

Keel install and the guard hook ​

tools/keel.js installs and updates Keel in a game (see Update Keel). keel-guard (.claude/hooks/keel-guard.js, a PreToolUse hook on Write and Edit) refuses any edit to a file listed in keel.json, with a one-line reason pointing at the Keel repo. It does nothing where there is no keel.json (the Keel repo itself).

Place attributes ​

Attributes do not survive Script Sync, so these live in the place itself. Set them in the Properties panel. Every one has a default written in its script (read with Setting.Get), so the game behaves the same if the attribute is missing or has the wrong type. Remember to save the place after changing one.

Formatting and linting ​

  • StyLua formats Luau using stylua.toml: tabs, 120 columns, double quotes, always parentheses on calls.
  • Selene lints using selene.toml (std = "roblox").
  • The binaries come from the VS Code StyLua and Selene extensions.
  • In VS Code: format on save is on for .luau and .lua.
  • For Claude Code: a hook (.claude/hooks/luau-check.js) runs after every file Claude writes or edits. StyLua formats it, Selene lints it, and the type checker (server.exe analyze from the VS Code Luau extension) reports errors in the edited file only. Problems elsewhere never block an edit.

Which note covers which file ​

Every note in Docs/Systems/ lists the files it documents in a code: list in its frontmatter. A second hook (.claude/hooks/note-lookup.js) runs after every file Claude edits outside Docs/ and names the notes that list that file, so only those need checking. It reads only the frontmatter, never the whole vault.

Editor support: sourcemap ​

VS Code's Luau extension needs to know which file is which Studio instance, or it underlines correct code like script.Parent.Vendor.Trove. tools/sourcemap.js reads src/ with Script Sync's naming rules and writes sourcemap.json; .vscode/settings.json tells luau-lsp to run it instead of Rojo. sourcemap.json is generated, so it is in .gitignore. If underlines come back after adding files, run node tools/sourcemap.js once, or reload VS Code.

It only knows scripts and folders from src/. Instances that exist only in Studio are unknown.

Vendored libraries ​

Outside libraries are copied into the repo, never installed by a package manager:

  • They live in a Vendor/ folder. The Loader, Defs.Boot and Entity.Boot skip any Folder named Vendor, so a library is never booted as a module.
  • Each is an unchanged copy of one pinned commit. Only two things are added at the top: --!nocheck and --!nolint as the first lines, then a comment block with the version, commit link and license.
  • They are never edited or reformatted: the hook skips any Vendor/ path, .styluaignore stops format-on-save, and selene.toml excludes them.
  • Code never requires Vendor/ directly. A re-export file next to it (Keel/Trove.luau, KeelServer/Data/ProfileStore.luau) is the path everyone uses, so swapping a library changes one file.
  • To update one: replace the file with a newer pinned copy, put the two directive lines back, and update its header.

Keel Setup plugin ​

tools/KeelSetup.lua is a local Studio plugin, owned by Keel and updated with it. Studio has no way to script Script Sync's connect, so the plugin automates everything around it:

  • creates the six root Folders that are missing, never touching one that exists;
  • creates the optional place attributes with their defaults, only where they have no value;
  • shows a checklist of the Folders and the disk folder each one must be connected to.

Install it once per computer by copying it into Studio's Plugins folder (Plugins tab, Plugins Folder) and restarting Studio. keel.js new prints this step. It is a convenience: a game works the same if you create the Folders by hand. See Connect Roblox Studio.

The Folder list in the plugin must match Docs/Systems/Boot and Folders.md; change both together.

Code layout skill ​

StyLua keeps blank lines but never adds them, so spacing between statement groups is a judgement rule: the luau-layout skill (.claude/skills/luau-layout/SKILL.md). Group statements by purpose, separate groups with one blank line, keep a guard clause apart from the work after it, and put a blank line before the final return.
