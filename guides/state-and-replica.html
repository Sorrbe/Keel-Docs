State and Replica ​

Ongoing values (cash, level, inventory) reach clients as state they can watch, not one-off messages. The server writes with Replica.Set; the client reads and observes with State.

How it is carried

Player state travels as two Net messages, Keel.Snapshot and Keel.Patch, that only Keel/State reads. Game code never listens to them, and State hides them. This is not Roblox replication. Privacy comes from the server never sending a player's Owner data to anyone else, and never sending None at all. World-object state (an enemy's health, a door) is different: it is the model's attributes, which Roblox replicates and streams with the model.

Declaring what is replicated ​

On the component, set Audience and a Default:

AudienceWho receives it
Owneronly that player (cash, inventory, quests, settings)
Publicevery player in the server (level, team, equipped item)
Nonenobody; stays on the server, but Set and Get still work on it
luau
return Entity.component({ Name = "Currency", Saved = true, Audience = "Owner", Default = { Cash = 0 } })

A saved component's section is the player's data table, so one Set both saves and replicates. An unsaved one starts as a copy of its Default and is lost when the player leaves. A saved component with no Audience is not replicated at all.

Server ​

luau
local Replica = require(ServerScriptService.KeelServer.Replica)   -- add "Replica" to Dependencies
Replica.Set(player, "Currency.Cash", 510)   -- Component.field[.field...]; nil removes
Replica.Get(player, "Currency.Cash")
Replica.Added:Connect(function(player) end) -- state exists and snapshots have been sent
  • Always write through Set. A direct write to the table is not sent.
  • The path must be inside a replicated component (not the component itself). The value must be plain data (finite numbers, booleans, strings up to 255 bytes, tables of those, at most 8 deep) and is copied. Set errors at the caller on a bad path or value, or if the player's data has not loaded.
  • When a player's data loads: they get a Snapshot of their own Owner and Public state; every other player gets a Snapshot of their Public state; they get everyone else's Public state. After that each frame's writes go out as one Patch per receiver, in write order, with only what that receiver may see.

Client ​

luau
local State = require(ReplicatedStorage.Keel.State)       -- Client/Main calls State.Boot() for you
State.Get("Currency.Cash")                                -- the local player's value, or nil
State.Observe("Currency.Cash", function(value) end)       -- now if it exists, then on every change
State.ObserveTable("Items", function(key, value) end)     -- each key now, then added / changed / removed (value nil)
State.Of(otherPlayer).Get("Look.Hat")                     -- another player's Public state
State.Attributes(model).Observe("Health", fn)             -- a world object's attribute
  • Observe waits if the path does not exist yet. A scalar fires only when it differs; a table fires on any change inside it.
  • Tables you are handed are live: read them, never write.
  • Other players' views contain only what the server sent (their Public components), so anything else reads nil.
  • All observers return a connection with :Disconnect(). In a View or Widget, add it to the Trove instead.
  • State.Attributes offers Get and Observe only.
