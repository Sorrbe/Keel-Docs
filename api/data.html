Data ​

Player data saving, on ProfileStore.

Server src/ServerScriptService/KeelServer/Data/init.luau

luau
local Data = require(ServerScriptService.KeelServer.Data)

Overview ​

Gives every player their saved data when they join and saves it as they play and when they leave, without a player ever playing on empty or someone else's data. Players whose data can't be loaded are kicked instead.

  • Owns: one ProfileStore per environment, each loaded player's data table, autosave, the version stamp and migrations, and kicking when loading fails.
  • Called by: Server/Main (Data.Configure, before Loader.Boot), Services (Get, Wait, Loaded, Leaving).
  • Fires: Data.Loaded, Data.Leaving.

Usage ​

A Service booted by the Loader (Name "Data"). Players load as they join and in Start.

What a player's data is: one plain table, keyed by component name, built from every Saved component's Default (Entity.Template), plus a version stamp:

text
{ _Version = 1, Currency = { Cash = 0 }, ... }

Change it only on the server. Plain data only (numbers, strings, booleans, tables of those; string keys; no mixed or sparse arrays).

luau
Data.Configure({ TestPlaceIds = {...}, Migrations = {...} })   -- once, before Loader.Boot
Data.Get(player)     --> the player's data table, or nil while loading / after leaving
Data.Wait(player)    --> yields until loaded; nil if the player left or the load failed
Data.Loaded          Signal (player, data): fired when a player's data is ready
Data.Leaving         Signal (player, data): fired just before the final save. A handler
                     must not yield (the save starts at once)
Data.StoreName(isStudio, placeId, testPlaceIds, version?) --> the store name for an environment

Behaviour to rely on:

  • Store name by environment: PlayerData_Studio (Studio), PlayerData_Test (a place in TestPlaceIds), PlayerData_Live (anything else), so a test place can never write live data.
  • DataVersion (whole-number attribute on ServerScriptService): 2 or more adds "_vN" to the store name, so bumping it starts every player on a brand-new store. Absent or 1 = no suffix.
  • Loading (yields; ProfileStore retries with backoff): waits for Entity.Boot so the template is complete, starts the session, runs Migrations, then fills in missing fields from the template. If it fails the player is kicked.
  • If another server takes the session, the player is kicked ("opened on another server").
  • Autosave every AUTOSAVE_SECONDS (ProfileStore's default is 300), a save on leave, and a save on shutdown (ProfileStore waits for all saves before the server closes).
  • FreshData (Studio only): set the attribute FreshData = true on ServerScriptService and every player starts with brand-new data in a throwaway store; nothing is read from or written to the real saves.
  • Studio without API access uses ProfileStore's mock store automatically.

Data.new(store, getTemplate, steps) builds an independent manager (no Players, no Entity): Load(key, userId?, cancel?), Get(key), Release(key), Ended. It exists so the rules above can be unit-tested with a mock store (Data.spec).

Lifecycle ​

This module is a Service booted by the Loader. The Loader calls these; game code does not.

  • Data:Init()
  • Data:Start()

Behaviour ​

  • Store name by environment: PlayerData_Studio in Studio, PlayerData_Test on a Test place, PlayerData_Live elsewhere. The DataVersion attribute on ServerScriptService (2 or more) adds _vN, starting everyone on a new empty store.
  • Loading waits for Entity.Boot, runs migrations, then fills in missing fields from the template.
  • A player is kicked (with a message, and the reason logged) on no session, a failing migration or a save from a newer version. Nobody plays on empty data.
  • Autosave every 60 seconds, on leave, and on shutdown.
  • FreshData (Studio only): FreshData = true on ServerScriptService gives every player brand-new data in a throwaway store.
