Entity ​

Things with identity and behaviour, built from components.

Shared src/ReplicatedStorage/Keel/Entity/init.luau

luau
local Entity = require(ReplicatedStorage.Keel.Entity)

Overview ​

A player, an NPC, a door or a plot is an entity. Behaviour lives in components (Health, Door, Currency) attached to it, so a player and an NPC can share the same Health code. A component can attach itself to every Instance carrying a CollectionService tag, and detach when the Instance is destroyed, loses the tag or (on the client, with StreamingEnabled) streams out.

  • Owns: the registry of components, the entity of each Instance, their ids, tag watching, and the saved-data template.
  • Called by: component modules (Entity.component), Server/Main and Client/Main (Entity.Boot), Services, Controllers and Systems (Entity.of, Entity.byId, Component.GetAll).
  • Fires: Component.Added / Component.Removed, entity.Destroyed.

Usage ​

Defining a component (one module per component, in Server/Components or Client/Components; the module returns what Entity.component returns):

text
local Door = { Name = "Door", Tag = "Door" }
function Door:Attach()
	-- self.Instance  the tagged Instance;  self.Entity  its entity (self.Entity.Id)
	-- self.Trove     cleaned on detach: put every connection and effect in it
	self.Trove:Connect(self.Instance.Touched, function() ... end)
end

return Entity.component(Door)

 Name      the component's kind ("Door"), unique within this side (server or client).
           Not an Instance's name: many doors share it. Saved data is keyed by it.
 Tag       optional. Every Instance with this tag gets the component, now and later.
 Attach    optional. Runs when attached; must not wait (use task.spawn). If it
           errors, the error is logged and the component is not attached.
 Audience  optional, for player state clients may see: "Owner" (only that player), "Public"
           (everyone) or "None" (server only). Needs Default. Entity.Replicated() lists these;
           KeelServer/Replica sends them to the right players.
 Saved + Default   optional, for components holding player data. Saved = true needs
           Default (a table of plain data). Entity.Template() returns a copy of every
           saved component's Default, keyed by Name, for KeelServer/Data.

Entity.component also gives the component:

luau
Door.Added    Signal fired with the component after it attached
Door.Removed  Signal fired with the component after it detached and its Trove was cleaned
Door.GetAll() every attached component of this kind
Door.Of(instance) the component on that Instance, or nil

Entities and their ids:

luau
local entity = Entity.of(player)   -- get or create the entity of an Instance
entity.Id                          -- unique string, never derived from the Instance's name
Entity.byId(id), Entity.get(instance)   -- find one (nil if none)
entity:Add(Currency)               -- attach; returns the component (the existing one if already attached)
entity:Get(Currency)               -- the component or nil
entity:Remove(Currency)            -- detach; false if it wasn't attached
entity:Destroy()                   -- detach everything; entity.Destroyed fires

Ids: a Player is "player_<UserId>" on both sides. Any other Instance gets "e<n>" on the server, which writes it to the Instance's EntityId attribute (always overwritten, so a clone never keeps its source's id). The client reads that attribute, so the server and client entity of one door share an Id. A tagged Instance whose attribute hasn't arrived yet waits for it (a warning after 10 s). A client-only Instance with no server twin gets "client_<n>".

An entity destroys itself when its Instance is destroyed (a moment later, not inside the Destroy call: Roblox's Destroying signal is deferred). A tagged entity whose last component detached (tag removed, streamed out) is destroyed too.

Entity.Boot(folder, ...) requires every component module in the folders (nil folders are skipped), then starts watching tags. Call it after Loader.Boot, so Services have connected to Added before the first components attach. Entity.WaitForBoot() yields until Boot has run (returns at once if it already has): a Service that needs every component defined (Template) calls it in Start.

Rules to rely on:

  • Attach runs once per Instance and component. Adding twice returns the first.
  • Detach always cleans the component's Trove; a failing cleanup is logged, not thrown.
  • A client may attach before the Instance's children have streamed in: use WaitForChild inside a task.spawn in Attach, or guard for nil.
  • Entity.newWorld() makes a separate registry, for tests (world.Destroy() cleans it up).

Functions ​

Entity.newWorld ​

luau
Entity.newWorld(): World

Makes a separate registry, so a test never touches the game's components.

Returns World — a World with the same functions as Entity, plus Destroy() to clean it up. A component from another world cannot be added.

Entity.component ​

luau
Entity.component(definition: any): Class

Defines a component: behaviour attached to entities. The module returns what this returns.

luau
local Door = { Name = "Door", Tag = "Door" }

function Door:Attach()
	-- self.Instance is the tagged Instance; self.Entity its entity; self.Trove is cleaned on detach
	self.Trove:Connect(self.Instance.Touched, function() end)
end

return Entity.component(Door)

Parameters

NameTypeDescription
definitionanyA table with Name (the component's kind, unique on this side) and optionally Tag, Attach, Audience, Saved and Default.

Returns Class — the component Class. It gets Added and Removed Signals, GetAll() and Of(instance).

Errors — A bad definition: no Name or a Name already in use; a reserved field (Added, Removed, GetAll, Of); a Tag that is not a non-empty string; an Attach that is not a function; Saved = true or an Audience without a Default table; an Audience other than "Owner", "Public" or "None"; or a Default with neither Saved = true nor an Audience.

Entity.WaitForBoot ​

luau
Entity.WaitForBoot()

Yields until Boot has run (immediately if it already has). A Service that needs every component defined, like Data, calls it in Start.

Behaviour ​

  • Attach runs once per Instance and component, must not wait, and if it errors the component is not attached.
  • Detach always cleans the component's Trove; Removed fires after the cleanup.
  • An entity destroys itself when its Instance is destroyed, a moment later.
  • With streaming, a tagged Instance leaving the DataModel detaches the client component; streaming back in attaches a fresh one with the same Id.
