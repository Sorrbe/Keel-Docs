LiveDefs ​

Changes chosen server-only game values on running servers, without a publish.

Server src/ServerScriptService/KeelServer/LiveDefs/init.luau

luau
local LiveDefs = require(ServerScriptService.KeelServer.LiveDefs)

Overview ​

A drop rate, a price, an AI value can be tuned (and A/B tested) from the Creator Hub

  • Owns: which configs are applied right now.
  • Called by: Server/Main (LiveDefs.Configure with the key list, before Loader.Boot), the console (livedefs), game code that wants to react (LiveDefs.Changed).
  • Fires: LiveDefs.Changed(key, value) when a key's applied value changes (value nil = back to authored).

Usage ​

while players are in the game. Roblox's ConfigService delivers the values; this applies them to the Defs, safely: only keys the game lists, only server-only kinds, and only values the field's type accepts. A bad value is logged and ignored, and the authored value stays.

A Service booted by the Loader (Name "LiveDefs").

luau
LiveDefs.Configure({ Keys = { "<Kind>.<entry_id>.<Field>" } })   -- Server/Defs/LiveKeys
LiveDefs.Active()    --> { [key] = value } of what is applied now

A key is "Kind.entry_id.Field". Set a config of exactly that name in the Creator Hub (Configs); remove it to go back to the authored value. Values arrive within about 5 minutes. Code must read entries through Kind.Get each time, not keep one, to see a change (see Defs.Override). If ConfigService can't be reached the authored values stay in force, with a warning. The Roblox limit is 100 keys per experience. Test in Studio without publishing: game:GetService("ConfigService"):SetTestingValue("<Kind>.<entry_id>.<Field>", value).

LiveDefs.new(deps, keys) is the pure part, for unit tests (LiveDefs.spec).

Lifecycle ​

This module is a Service booted by the Loader. The Loader calls these; game code does not.

  • LiveDefs:Start()

Behaviour ​

  • Only server-only kinds can change, and only values the field accepts. An invalid value is logged (Warn) and ignored; the authored value stays.
  • Create a config of exactly the key's name in the Creator Hub (Configs); delete it to go back to the authored value. Roblox allows 100 keys per experience, and values reach running servers within about 5 minutes.
  • If ConfigService cannot be reached, authored values stay in force, with a warning.
  • Code must read entries through Kind.Get each time, not keep one, to see a change.
  • Test in Studio without publishing: game:GetService("ConfigService"):SetTestingValue("&lt;Kind>.<entry_id>.&lt;Field>", value).

See Defs: live tuning.
