Defs ​

Typed game data (what things ARE), checked at boot.

Shared src/ReplicatedStorage/Keel/Defs/init.luau

luau
local Defs = require(ReplicatedStorage.Keel.Defs)

Overview ​

Items, enemies, shop lists and the like are authored as plain tables. A kind gives each of them a shape and permanent string ids, and boot checks every entry against its shape and every cross-reference, so a typo is caught before any player is affected. See Docs/Systems/Defs.md.

  • Owns: the registry of kinds and their entries, validation, and Boot.
  • Called by: Defs modules in Shared/Defs and Server/Defs (define kinds), Server/Main and Client/Main (Defs.Boot), Services and Controllers (read entries).
  • Fires: nothing.

Usage ​

Defining a kind (one module per kind; the module returns the Kind):

luau
local Items = Defs.kind("Items", {
	DisplayName = Defs.String(40),
	Price = Defs.Int(0),
	Weapon = Defs.Optional(Defs.Ref("Weapons")),
}, {
	sword_iron = { DisplayName = "Iron Sword", Price = 50, Weapon = "blade" },
})

return Items

Reading: Items.Get("sword_iron") -> entry or nil, Items.Has(id), Items.Ids() (sorted), Items.Entries (id -> entry, read-only; Net.OneOf(Items.Entries) works). Entries are frozen after validation. Ids are lowercase letters, digits and underscores, starting with a letter. They are saved and sent, so never rename one.

Fields (see Keel/Defs/Fields): String, Number, Int, Bool, OneOf, Ref, List, Struct, Optional. A Ref names another kind and checks the id exists.

Boot: Defs.Boot(folder, ...) requires every module in the folders (see Keel/Modules.Collect; nil folders are skipped), then runs Defs.Validate(). Validate in Studio errors with every problem listed, which stops boot. On live servers each broken entry is logged and disabled (removed), and so is any entry that referred to it. A kind's own shape being malformed errors at Defs.kind.

Layering: a shape may only reference kinds that Boot loaded on that side, so Shared Defs can't refer to Server Defs (the client never has those). Defs.newRegistry(strict) makes a separate registry, for tests.

Defs.kind ​

luau
Defs.kind<T>(name: string, shape: Shape, entries: { [string]: T }): Kind<T>

Defines a kind of game data: its typed shape and its entries. A module returns the Kind it makes.

luau
local Items = Defs.kind("Items", {
	DisplayName = Defs.String(40),
	Price = Defs.Int(0),
	Weapon = Defs.Optional(Defs.Ref("Weapons")),
}, {
	sword_iron = { DisplayName = "Iron Sword", Price = 50, Weapon = "blade" },
})

return Items

Parameters

NameTypeDescription
namestringThe kind's name ("Items"). Unique; a duplicate errors.
shapeShapeA table of fields (Defs.String, Defs.Int, Defs.Ref, ...) every entry must match.
entries{ [string]: T }The entries, keyed by permanent id (lowercase letters, digits and _, starting with a letter).

Returns Kind<T> — a Kind with Get(id), Has(id), Ids() (sorted), Entries (read-only) and Name.

Errors — A malformed shape, or a duplicate kind name, errors here (a code mistake). Entry mistakes are found later, by Validate.

Defs.Validate ​

luau
Defs.Validate(): { string }

Checks every entry of every kind: id format, no field outside the shape, every required field present, each value passes its field, and every Ref exists.

Returns { string } — the list of problems, each reading like Items.sword_iron.Weapon: no Weapons entry "blde". In Studio (a strict registry) any problem errors with all of them listed, which stops boot. On a live server each broken entry is logged and disabled, and so is any entry that referred to it.

Defs.Boot ​

luau
Defs.Boot(...: Instance?)

Requires every module in the folders (through Modules.Collect), then calls Validate. Server/Main calls it with Shared/Defs and Server/Defs; Client/Main with Shared/Defs only.

...Instance?Folders to load. The first is the shared one (clients load it too); kinds from later folders are server-only. A nil folder is skipped.

Defs.Override ​

luau
Defs.Override(kindName: string, id: string, field: string, value: any): (boolean, string?)

Changes one field of one entry of a server-only kind while the game runs. LiveDefs calls it for ConfigService values.

Parameters

NameTypeDescription
kindNamestringThe kind's name.
idstringThe entry's id.
fieldstringThe field to change.
valueanyThe new value. It must pass the field, and must not contain a Ref.

Returns (boolean, string?) — ok, reason. Refused for a kind clients can see, an unknown kind, entry or field, a value the field rejects, and any value containing a Ref. The entry is replaced by a frozen copy; the authored table is never touched. Code must read entries through Kind.Get each time to see a change.
