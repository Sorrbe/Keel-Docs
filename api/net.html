Net ​

Defines network messages and sends them, checked and rate-limited.

Shared src/ReplicatedStorage/Keel/Net/init.luau

luau
local Net = require(ReplicatedStorage.Keel.Net)

Overview ​

The one way game code talks between server and client. Every message declares what it carries and how often a client may send it, and the server checks both before any handler runs, so no handler can forget validation. It also holds back messages to a joining player until their client is ready.

  • Owns: message definitions, sending, the ready handshake and its per-player queues, and the unreliable channel. Net/Screen does the server's receive checks (rate limit, then Args); Net/Args holds the argument types. Runs on Packet (Keel/Packet), which does the batching and binary encoding.
  • Called by: Shared/Net.luau (definitions), Services and Controllers (send/listen), Server/Main and Client/Main (boot: WaitForServer, ClientReady).
  • Fires: Net.PlayerReady(player) on the server when a player's client is ready.

Usage ​

Defining (in Shared/Net.luau, required by both sides; names are "Feature.Action"):

luau
Net.event("Shop.Buy", { Net.OneOf(Defs.Items) }, { Rate = 5 })
Net.request("Trade.Offer", { Net.Int(1, 1000) }, { Rate = 2 })
Net.broadcast("Round.Ended", { Net.String(50) })
Net.unreliable("Aim.Direction", { Net.Vector3() }, { Rate = 30 })

Kinds and their methods:

luau
event       fire-and-forget, either way.
            client :FireServer(...), :OnClient(fn(...))
            server :FireClient(player, ...), :OnServer(fn(player, ...))
request     the client needs an answer: ok, reason.
            client :Invoke(...) -> (ok, reason?)   (waits; false, "timeout" after 10 s)
            server :OnInvoke(fn(player, ...) -> (ok, reason?))   (one handler)
broadcast   server to many.  server :FireAll(...), :FireNear(position, radius, ...)
            client :OnClient(fn(...))
unreliable  high-rate, replaceable data (aim, positions). Like event, plus server
            :FireAll(...). Payload must stay under 900 bytes. May arrive out of order or not at all.

Rules to rely on:

  • A client may send a message only if it has a Rate (sends per second per player). Without one, the server ignores client sends and FireServer/OnServer error. request always needs a Rate; broadcast never has one.
  • Server receive order: rate limit, then argument checks, then handlers. A rejected message is dropped (a request answers false, "rate limited" / "invalid"), and a Warn names the player, message and reason (at most once per 10 s each).
  • Handlers still check game rules (ownership, distance, cooldowns, money).
  • Every send checks its own arguments first and errors at the caller: a bad value is our bug, so it surfaces where it was made.
  • Server sends to a player whose client isn't ready yet are queued (up to 256, then dropped with a Warn) and delivered in order once it is. Unreliable sends to them are dropped.
  • Limits: 256 messages per game (Packet's one-byte ids), 8000 bytes per player per frame from a client (Packet drops more), 128 requests waiting at once per client.

Boot: Server/Main requires Shared/Net before booting. Client/Main requires it, calls Net.WaitForServer(), boots the Controllers (Init connects listeners), then Net.ClientReady(). Sending from a client before WaitForServer has finished errors: send from Start or later.

For tests: message:_Receive(player, ...) and request:_Invoke(player, ...) run the server receive path directly (what Packet's listeners call).

Message ​

What Net.event and the other constructors return. Methods:

MethodSideDoes
FireServer(...)clientsends to the server (needs a Rate)
FireClient(player, ...)serversends to one client
FireAll(...)serversends to every client
FireNear(position, radius, ...)serversends to clients near a position
OnServer(handler)serverlistens; handler(player, ...) runs after the Rate and argument checks. Returns a Connection
OnClient(handler)clientlistens. Returns a Connection

OnInvoke(handler)serverfor a request: handler(player, ...) returns ok, reason? (one handler only)

Behaviour ​

  • Server receive order: Rate, then argument checks (extra values are rejected too), then handlers. A rejected event is dropped; a rejected request answers false, "rate limited" or false, "invalid".
  • A request answers false, "error" if its handler errors or returns the wrong thing, false, "no handler" if none is set, and false, "timeout" after 10 seconds.
  • Every send checks its own arguments and errors at the caller.
  • Limits: 256 messages per game, 8000 bytes per player per frame from a client, 128 waiting requests per client.

See Networking and Add a network message.
